# Native count-window metadata kernel — prospective only

`window.py` checks original supplied-archive task ownership, Rust hourly success maps (negative values never hidden by aggregate `max(n,0)`), and required development count windows. It reuses verbatim original `coverage_gaps`, `event_coverage`, `_hour_of`, and `archive_start`; source SHA and AST parity are tested. Training uses7200seconds and validation60seconds on the unchanged manifest onset. Original gap/failure dispositions remain attached even when a gap lies outside this required window.

The daily branch implements the original daily-ingestion calendar contract and explicitly does NOT claim extraction-bound archive ownership, historical parser binary identity, strict iterator error completeness, or peer-session continuity. Extra supplied files are not mislabeled missing. Missing/negative hours or failed acquisition cannot establish successful coverage. The restored native branch verifies the exact successful URL set bound to each original part; old URL-only timestamps use the ORIGINAL archive_start fallback and fixed collector rotation, never observed-content timestamps.

This kernel does not authorize or admit coverage, change cohorts, parse source payloads, or fit anything. Full canonical-source binding, retained failure treatment, required-window evidence and separate native consumer admission remain necessary. `build_actual.py` is an unfrozen local composition helper under development, not part of this kernel freeze.

Validation: `.venv/bin/python -m pytest -q .agents/operations/newperiod-count-native-window-20261024/test_window.py` —15passingtests. Cases include genuine original helper AST parity, task URL/population mismatch, failed hourly parse masking, missing hours, archive gaps outside/inside the required horizon, train/validation distinction, extraction truncation, daily extra archives, and legacy native timestamp fallback.
