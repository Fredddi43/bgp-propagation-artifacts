# Custodian label preparation reader: code-only review

The mandatory N label-table handoff had reviewed pure builders but no operational reader. This isolated candidate calls the unchanged newperiod-custodian-preparation-20261020 prepare.target_status and prepare.label_table. No existing scientific source, master manifest, predictor or evaluator is modified.

run accepts already-read bound plan/authority bytes plus externally authenticated expected hashes. The authority must explicitly approve prepare_labels_only for this exact plan hash. This is an input contract, NOT an authority issuer or provenance authentication service. Actual execution requires a separately reviewed concrete plan, actual authorized custody evidence, frozen source/runtime/resources and owner invocation; the synthetic authority fixtures grant nothing.

The plan explicitly enumerates both masters, extension decision, each event's existing status and (for scorable events) separate summary/coverage/membership references, exact sizes, total byte budget, custody root, access log and output. No glob, recursive discovery or path inference exists. Current master() does not bind coverage.json, so a separately authorized exact coverage ref is mandatory. Input_status never determines target status. Existing status must match target_status's actual source coverage result. Reads run in two cohort-wide passes. Pass A reads every event's status. A censored status must pass prepare.target_status's declared-censor checks (event, panel, onset, target end, status and a non-blank reason). Its unused payloads are never opened. A scorable status must equal, exactly, the canonical document prepare.target_status emits, built from the master row, panel and planned refs alone: canonical +00:00 clock spelling, no extra keys, no reason. This check runs before that event's summary and coverage are read. For scorable events only, pass A then reads summary and coverage and checks their identity and completeness. Pass B reads membership payloads only after every event has passed pass A, then repeats the actual target_status equality as a defence check. So invalid status, summary or coverage metadata on any event, including a later one, refuses with no membership read. The only refusals left after a membership read are that file's own hash/size/type checks and its decode/content checks in label_table, which depend on the data. Censored declarations are validated and retained; unused censored payloads are never opened.

Before the first log record, every planned input must already be a regular file (lstat S_ISREG), so a FIFO or device path is refused without any log entry or open. Each protected read invokes the existing custodian_access_log.log_read, then fsyncs the exact configured log and its directory BEFORE opening the input with O_NOFOLLOW|O_NONBLOCK. O_NONBLOCK means a FIFO swapped in after preflight opens at once and is refused by the post-open S_ISREG check instead of blocking; it has no effect on regular files. Source must be a regular file of exact size; bounded read/hash checks precede JSON/parquet decoding. Canonical nonsymlink paths are required. Logger configuration must equal the explicit plan path. Output is exclusive, inside custody, and uses unchanged write_candidate; its hash is calculated from the same serialization in memory, without a further protected read. Output publication grants no freeze/seal/evaluation/release authority.

81 tests pass: 41 reader tests plus 40 existing preparation tests. Tests use only synthetic temporary files and real unchanged scientific builders. They cover durable log-before-open, log/fsync failure, changed hash/size, decode ordering, external authority mismatch, missing coverage/status, exact cohort coverage, path escape/symlink, byte budget, censored skip and exclusive output. They also cover later-event metadata refusal with no membership read, metadata-before-membership ordering, and static or swapped FIFO refusal without blocking. Ruff passes.

Scope limits: this is only a callable operational candidate, with no CLI or actual execution. It does not generate the externally approved read plan/status/censor evidence, infer missing coverage, authenticate a purported reviewer itself, produce projection/slice predictions, attach roles, or resolve frozen N arm inventory. Retained dependencies and actual authority must be reviewed in the eventual execution package. Filesystem namespace must remain under the authorized custodian's control; no concurrent hostile directory mutation is assumed. Failed runs are not automatically retried. All actual protected-read, label-generation, admission, unseal, fit, scoring and transport authorities remain absent from this code review.
