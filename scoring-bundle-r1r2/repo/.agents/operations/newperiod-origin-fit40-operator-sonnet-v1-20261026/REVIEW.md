## Design
- Structure copied from the accepted timing40 v28 operator. `writer.py`, `transport.py`, `ssh_contract.py` are byte-identical copies (test `test_science_and_helpers_byte_identical`). Science is unchanged: the worker calls the exact `family.fit_cell(plan, output, device='cuda')` (entry.py:64-92) obtained through `adapter.family_with_reader` (entry.py:69), with family.py / reviewed_build.py / adapter.py / forecast_train.py hash-pinned (prepare.py PINNED_SOURCES).
- Two families = two row-funded namespaces (v44 rows `origin_fit_twenty` valid, `origin_invalid_twenty` invalid, 23622320128 B each; phase checked in `prepare.phase`, newest-compatible check in operate.py:54+). Each family has four actions (stage, submit_held, release, capture) = 8 distinct root onces, each with its own `actual-<valid|invalid>-<action>` directory consumed before the first remote attempt. Array `0-19%1`, concurrency fixed at 1 (reviewed planning value).
- Cells: the 20 roles per family come from the accepted full40 followup through the reviewed `bind.py` (`prepare.role_cells`); the 20 `plan` dicts (the nine actual `fit_cell` keys) come from `bind.prepare` with a fully populated bindings object (`prepare.plans`). Output layout: `output/<arm>/{started,complete}.json` + `fit/{checkpoint.pt,validation_predictions.json,fit_receipt.json}`; caps 128/512/128 MiB via the unchanged writer (matches the reviewed capacity proposal).
- Custody: zero appends anywhere (test `test_no_custody_append_and_fsize`). FSIZE 2 GiB in job.sh (`ulimit -f 2097152`), entry.py:16/58-60 and remote helper; refusal if custody EOF + all-writer growth >= 2 GiB - 64 MiB (remote.py:56 OF_R06, entry.py:60 OF_E13, operate.py:87 OP_CUSTODY_CEILING). Observed custody EOF 1500270395 B is below that ceiling.
- Remote refusals: remote.py raises `ValueError('OF_R##')` with one code per check (AST test enforces uniqueness; unclassified exceptions print OF_R99, no text). entry.py uses OF_E##, local checks OP_ names (also unique). Failed cells retain `failed.json` with exception type only (no message, to avoid leaking data).
- Run with `/usr/bin/python3 -I -B` from `/tmp` or any cwd without operator.py; operate.py refuses non-isolated start.
- Outer evidence (what `fit_cell` itself does not enforce) is checked at release: (1) local `prepare.release_bundle` requires an independent `s3_acceptance` document binding both own-family boundary refs, and an independent `fit_input_review` binding `bindings_sha256`, phase, nine true flags (boundaries, construction, source inventory, history-r3 library complete, sealed gates, retrospective releases, metadata recipe+coverage, validation precision, reader adapter) and every reference of the family verbatim; (2) remote `check_evidence` hashes every referenced evidence file (bytes only, 1 GiB/file, 8 GiB total) and requires each boundary/construction/gate actual review to be passed, independent (not author list, not author sessions) and to embed its subject `{path,sha256}`.
- Release installs plans.json, s3-acceptance.json, fit-input-review.json, release.json + release.sha256 exclusively; entry.py refuses unless that pair, manifest, operator files, staged sources and installed hashes match.
