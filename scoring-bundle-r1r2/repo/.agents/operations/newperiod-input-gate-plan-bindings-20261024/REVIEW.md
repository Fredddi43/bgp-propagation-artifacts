This binder creates the unchanged original paired B plan after independently accepted successful A witnesses. It issues no B authority and does not run the gate. The original core or temporal gate remains responsible for full report, inventory, assembly, shard, trace, mount and exported-byte verification.

Each exact independently approved request contains profile core|temporal, the existing source manifest reference, and six refs per horizon: actual A plan, A authority, successful witness, construction, original inventory and original assembly. All paths are fixed before reads. Exactly nine SHA-checked metadata JSON documents are opened: source manifest plus four per horizon. Six additional metadata paths (inventory, assembly and audit report per horizon) receive regular canonical lstat only. Existing sized stage/master/export refs are copied from the witnessed A plan; no tensor/source/trace paths are opened.

Module hashes copied into B are first matched against the separately pinned source closure. A plan/authority/code/documents/report success, unchanged primary library delay, profile and horizon ancestry are checked. Full reference counts come from the original declared export list. Original B checked_inputs accepts emitted documents for both profiles in tests; mismatches fail before publication. Original B will still independently verify all evidence; this metadata binder is not an audit pass.

One full-scope append-only custody log record is fsynced before metadata reads/stat. Bounds: 64 MiB/file, 256 MiB aggregate reads, 2 GiB address space, 180 CPU seconds, 120 wall seconds, one fresh output <=1 MiB. Shared log append completes before the output FSIZE bound. Output is gate-plan-bindings-v1/plan-input-gate.json in the fixed original profile root. Failures preserve partial state and never retry. An enclosing independently approved exact invocation and actual source request are required; current code readiness is not execution authority.

Actual successful A witness refs remain unavailable while the two A operations run. No pending or fabricated hashes are placed in an execution request.
