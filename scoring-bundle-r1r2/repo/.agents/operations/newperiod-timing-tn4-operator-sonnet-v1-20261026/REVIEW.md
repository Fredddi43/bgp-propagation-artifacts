# T-N4 timing construction operator + single-horizon input-gate producer (sonnet, session <SESSION_ID>)

Fills N4-F3 (stage/submit_held/release/capture operator) and N4-F5 (single-horizon gate producer) of `newperiod-timing-tn4-sonnet-v1-20261026`. Source, templates and synthetic tests only. **Nothing issued, staged, submitted, released, captured or written remotely; no ssh at all during authoring.** `execution_authorized=false` everywhere. Tests: `tests.txt` / `verification.json` (28 tests, .venv python).

## Files
`common.py` pins, reason codes, ROOT SSH argv, `controls()`, `independent()`, schedule/queue/sacct parsers, cap + custody rules · `operate_tn4.py` the once operator (4 actions) · `make_request.py` deterministic request/predecessor derivation · `remote_wave.py` remote programs (two reviewed snippets verbatim + stat-only capture) · `tn4_gate.py` remote single-horizon gate producer · `make_gate_request.py` · `gate_once.py` ROOT once launcher for the gate · `templates/` (all FALSE) · `reason-codes.json` · `root-sequence.json` · `test_operator.py` · `verify.py`.

Successor package `controller.py` (`stage`, `submit`, `held_job`, `scheduler_script`, `batch_rows`: called, not copied; its ssh argv is checked equal to ROOT standard on every call via `split_argv`) and `wave_contract.py` (`schedule('timing')`=36 waves, `release_targets`, `authorization`, `admit`, `census`) · `release_once_tn4.held()` · its two remote snippets verbatim (tested by substring) · timing40 `ssh_contract` argv (tested equal) · tn4 `transport.exchange` (bounded; keeps stdout/stderr of a refused call) · `phase_compat` v2 · H1 v3 `operate3/capture3` patterns: CONSUMED then per-call recheck + intent/return records, STOPPED, layout/task-state checks, sacct terminal rows, two-pass capture >=300 s apart, A-model growth checks.

## Operator (`operate_tn4.py`, `python -I -B`; authority kind `ROOT_ONCE_TIMING_TN4_OPERATOR_V1`, release uses the contract's `root_protected_wave_once_v1`)
Fixed actual dirs `actual-stage`, `actual-submit_held`, `actual-release-NN`, `actual-capture-NN` (NN 00..35). Each: CONSUMED before the first remote byte; every remote call re-runs the full gate (authority, pins, review, adoption, phase compat, control snapshot, predecessor acceptance, request re-derived byte-equal) and writes intent/return records; any failure -> STOPPED.json, never retry/cancel/overwrite.
1. **stage**: `controller.stage` through a runner adapter (host/command parsed from argv, argv must equal `ssh_argv`).
2. **submit_held**: `controller.submit` (exclusive claim + one held batch of 24 jobs), then `scheduler_script(readback)` + `held_job` for all 24 + whole 148-task grid `PENDING|JobHeldUser`.
3. **release N**: held readback of targets (`release_once_tn4.held`), full-grid squeue `before`, custody stat (identity pinned by adoption, EOF + all remaining growth < 2GiB-64MiB), reviewed snapshot, `wave_contract.admit` (refusal text kept, code `TN4OP_ADMISSION_REFUSED`), local permission copy, immutable `wave-permission-NNN.json` readback, admit again, grid re-check, `scontrol release <exactly targets>` (empty output required), post-states. The N4-F4 storage rows must exist or admit refuses (tested).
4. **capture N**: `sacct -X -n -P --format=JobID,JobIDRaw,State,ExitCode,Restarts` — **exactly 5 fields, `-P` has no trailing delimiter; a trailing `|` or other field count refuses** (`TN4OP_SACCT_TRAILING_DELIMITER`/`_FIELD_COUNT`; origin-fit40 lesson), squeue `after` layout, then one stat-only remote program (two passes >=310 s apart, reviewed census over the whole protected root, own-record stats, intent/worker-intent/done JSON <=8 MiB only). Zero writes, zero appends, no payload.
Release N>0 needs the capture N-1 actual AND an independent acceptance; `make_request.predecessor` builds the `admit` predecessor from them (before census = permission snapshot, after census = capture), never by hand.
**Control snapshot** = all names containing `ROOT-`/`REVIEWER-` (<=4 MiB) in the five control dirs, authority path removed (mirror S2 v4 `controls()`; tested vs its source). **Independence** = S2 v4 `independent()` normalization (casefold, `normpath('/'+x.lstrip('/'))`, author names/sessions incl. `/SESSION`, `.../sonnet` suffix) plus author_sessions/author_worker.

## Per-file cap decision (explicit, fail-closed)
- The reused plan already carries `resources.file_bytes = 2 GiB` per group (`build_packets.py:64`; runner `RLIMIT_FSIZE` soft=file_bytes, hard=max(2GiB,file_bytes); `controller.groups` and `runner.validate` require >=2 GiB). The **512 MiB** value belongs to the superseded d300 dev plan (observed 499.8 MiB = 97.6 % of it); it is refused by name (`TN4OP_PLAN_FILE_BYTES_SUPERSEDED`) and anything other than exactly 2 GiB refuses (`TN4OP_PLAN_FILE_BYTES`); the pinned runner must contain the exact FSIZE line and phase caps (`TN4OP_RUNNER_FSIZE_LINE/_PHASE_CAPS`).
- Caps: build shard files **2 GiB**; manifest/assemble/master/export/audit files **512 MiB** (runner constant + `FileLimits`/`Budget.per_file`; H1 v3 export/audit ran under the identical runner). 2 GiB build keeps the d300 file at ~24 % of the cap.
- Capture refuses any own file at/over its cap (`TN4OP_FILE_AT_CAP`: a file at the cap means the writer hit EFBIG) and flags >=90 % `near_cap`; the next release then needs `file_cap_reviewed: true` in the independent capture acceptance (`TN4OP_PRED_CAP_REVIEW`). Adoption must restate the caps (`TN4OP_ADOPTION_FILE_CAPS`).
- **Open for Codex**: confirm the 512 MiB non-build cap is adequate for the timing export (many small per-event files expected; no timing export has run) — if not, a successor plan, not this operator, must change it.

## Custody / FSIZE
Operator, remote helpers and the gate append nothing: local FSIZE 4 MiB, remote helper FSIZE 16 MiB, gate FSIZE 64 MiB (all far below the 1,526,065,393 B log: an accidental append fails EFBIG). The jobs append (runner `custody_scope`, 148 tasks x 2 roles x 64 KiB <= 19.4 MB): adoption must show jobs hard FSIZE 2 GiB > log EOF and EOF+growth < 2GiB-64MiB; release and every capture re-check log identity (dev/inode), no shrink and the ceiling (`TN4OP_CUSTODY_*`).

## Single-horizon gate (`tn4_gate.py`, one per d5/d10/d300/d900)
Request from an independent group-audit acceptance. Reads only: staged plan, audit `done.json`, audit.json, manifest, master, export manifest, inventory, cohort (all bounded, O_NOFOLLOW, sha-pinned); validators are the staged reviewed `forecast_manifest`/`forecast_inputs` whose imported bytes must equal plan.files. Checks: done chain (plan/group/phase audit/gate_issued False/result refs under the group's own records), cohort 1124 ids + `dc8f0976`, population == export, custody chain hashes, contracts equal across export/master/construction, original `source_inventory`, audit report (passed, no failures, rows/tensors counts, auditor == staged original, library digest/delay), then the verbatim consumer predicates (`load_inputs` 278-283 + freeze; test compares the consumer source). Output exclusive `xb`, 0444. **Decision for Codex (D-GATE-1)**: it opens no export input (audit already hashed every row) and appends no custody record, following the H3 integration-gate precedent; the paired r5 producer instead logs and re-streams every input. If you require the re-stream, a logged variant with FSIZE>log is needed (not authored). Not authored: a witnessed-audit (syscall trace) binding — the timing audit has none.
