The shared validator persists validity but not the chosen snapshot date. Existing validity summaries mix in outcome statistics and are not a safe substitute for this counts-only request.

This packet proposes one root-only read of exact finalized, unstratified validation tables, projecting **only event_id**, plus pinned metadata inventories of available daily snapshots **at original validation time**. It reconstructs the shared validator's same-day / latest prior 1–7 day / unavailable decision. It does not decode validity, prediction labels, or scores. File hashes necessarily read physical input bytes for identity. No archive payload is read. Output is integer event counts per period, including a denominator and outside-period count; no per-event IDs, dates, actors, error values, or rows leave the worker. Optional cross-midnight counts are omitted. R2 actor-day support remains sealed.

The proposed denominators are all finalized origin-validation events partitioned by detection date: development [2025-01-01, 2026-09-01), new period [2026-09-01, 2026-10-16). These are NOT incident/onset-window counts or validity-stratum counts. Independent population review must approve these denominators and exact complete source tables before use; duplicate IDs across tables fail closed. Snapshot availability must be proven equivalent to the availability used for every included original validation. A current directory listing alone cannot establish historical fallback use, especially after archive backfill. Without that evidence counts remain PENDING; no inferred zeros or fabricated provenance.
