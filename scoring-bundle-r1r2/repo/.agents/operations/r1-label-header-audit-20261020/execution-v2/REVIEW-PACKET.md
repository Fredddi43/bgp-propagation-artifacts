## Scope and remaining limitations

Proposed 128 CPU jobs × 2 CPUs, partition `cpu`, no node selection, 10 GiB physical allocation/8 GiB hard address-space, four-hour limit, no requeue/retry. An afterok gather uses two CPUs. Existing full opaque verification continues independently and is not rerun or modified.

Each worker streams SHA256 over its exact targets as opaque bytes, matches the existing gate/partition/linkage digests, then reads only declared ZIP end/central-directory metadata or the one Parquet footer. It keeps the authenticated inode open for `/proc/self/fd` header reopening and compares inode/size/timestamps before and after. NFS st_dev is client-local and is only compared within one open; it is not compared across nodes. No pickle/NumPy/tensor/forecast deserializer, array values, Parquet row data, or member APIs are used. Parquet footer bytes may encode statistics; the parser does not request or emit those statistics. This scope must be explicitly authorized in final execution review.

Headers do not prove safe behavior on adversarial containers. The exact existing producer/gate lineage must support trusting these byte identities; reader assertions alone cannot do that. Output records explicitly decline adversarial-layout and resident-memory proofs. Target memory derivation is a separate next step. R1 remains closed; N/protected2026 reads, fits, predictions, scoring, freeze/seal and automatic retry are forbidden.

Each shard has a deterministic disjoint target subset, ≤3 GiB opaque I/O, 256 MiB header reads, 64 MiB output. The gathered output has a 2 GiB hard file limit. Staging requires ≥32 GiB free, covering 128×64 MiB shards, gather, staging and reserve. Root transport validates the full union against inventory before creating remote roots and submitting once. Gather verifies all success receipts and exact report digests, every expected target once, and no failed shard.
