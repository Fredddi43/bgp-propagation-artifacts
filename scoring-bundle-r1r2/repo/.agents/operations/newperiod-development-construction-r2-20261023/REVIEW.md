# Development construction and complete audits

This is a local candidate, with no host mutation or scientific execution. The approved six-file kernel is unchanged. H1 can be packaged and independently admitted without H3 or timing being ready: every plan retains all ten arm/horizon entries, and only its explicitly admitted groups require resolved inputs. Fixed per-group remote submission claims prevent another package or local records directory from duplicating that group.

The chain is build array -> assembly -> audit array -> audit finalization. Build shards preserve every original row; audit assignments and finalization require the complete fixed grid. The H1 wrapper executes the original metadata(), load_histories(), and audit_chunk() unchanged, with a truthful new build-adapter identity under the shared job admission. H3 and timing use their separately frozen audit callables. H3 finalization also emits the separately reviewed construction-status inventory; no integration gate is issued here.

Only three explicit ancestor products may be resolved after construction: development manifest, construction receipt, and (H1 only) history receipts. Every independent source, gate, cohort, recipe, inventory, history-table and actual retrospective-release reference remains bound in the submitted template. No R1 completion or independent approval is invented.

Each actual job verifies the exact complete cache-free control/source tree, independent release binding, scheduler identity, full existing private-runtime verifier, original source/gate authorization, and resource bounds. The private editable environment is unchanged. Scripts use a clean environment, CPU partition, no node pinning, no requeue and fixed held arrays. Scheduler submission and fresh readbacks are batched. Release occurs once after all predecessor jobs are still held and one independent aggregate admission has been bound remotely. Ambiguous or partial responses are terminal; stdout/stderr and exclusive claims are preserved.

Storage admission sums maximum retained writes for every admitted build shard, assembly and audit shard, per-concurrent-audit scratch, complete code/control bytes, bounded per-task logs, the free-space floor, and explicit concurrent reservations. It does not multiply the same free bytes into independent per-job admissions. Each scientific child runs under wall, address-space, CPU and file limits; a supervisor bounds each stdout/stderr stream and kills/reaps its own process group on failure. The reviewed linear writer budget is retained. Its narrow extension accounts for deletion only of its own registered scratch files; no source cleanup occurs. Every phase reconciles actual final files once, without repeated recursive filesystem scans.

Actual launch still requires resolved source/gate/release metadata, numerical runtime/resource identities, aggregate storage evidence, exact separate execution reviews, held scheduler readback, and independent release binding. The H3 compatibility adapter and complete H3/timing wrapper reviews remain separate evidence; this client does not assert their approval.
