# Primary master, exports and witnessed-audit binding

This concrete local candidate continues the independently reviewed protected construction chain: two horizon master jobs after the exact upstream assembly array, four independent core/temporal export jobs after masters, then one metadata binding job. Every actual task checks the full reviewed source/runtime closure, completed R1 release, sealed development manifests, exact construction plan and successful producer receipts. Original master/export function bytes and full reference/status populations remain unchanged. No new actual data, authority, fit, score or source admission is produced locally.

`package-v1/client.py` is the executable local client once its plan.json has actual references and separate exact approval. It reuses the reviewed exclusive staging/submission pattern and clean scheduler environment. Submission intent and result are durable; uncertain/failed submission never resubmits. All jobs use cpu without node pins, two CPUs/256GiB/four hours each, and Slurm afterok/kill-on-invalid-dep. There are no routine permission pauses between successful phases. Source package/pipeline self-pins and original construction controller pins are mandatory. The client is invoked from the assembled package, not the author directory.

Original master classification retains unavailable_no_input, source_failure and technical_failure statuses and their original evidence, including available rows with incomplete windows. Core and temporal export both retain every master event. The unchanged original exporter validates source hashes, tensor provenance, clocks, populations, labels excluded from payload, messages for temporal, and status receipts. The operational producer wrapper adds only output-location, per-file and cumulative storage limits: torch.save is wrapped before native serialization, Python write opens are checked, and neither tensor nor metadata content is transformed. Original graph/source payloads stay in custody. There is no direct untraced audit invocation.

The final binding job emits exact sized CORE witness plans for the existing private gate v5, including every actual exported tensor/status, available source graph, original stage/construction/master/export, history years, actual private code map and tracer identity. It does not issue plan authority or execute the witness. Actual sized graph references reuse their original producer digests and stat sizes; the unchanged witness hashes all actual bytes before use. Authorities and phase execution approval must bind the generated plans. This is the genuine existing witness boundary, not a new gate. The already reviewed private launcher and host suite are reused; no suite rerun is proposed.

A real separate compatibility gap is explicit: gate v5 only accepts primary-core. Temporal exports are prepared but not admitted by a core gate. This packet marks temporal_gate_ready=false; a narrowly reviewed temporal-profile gate remains necessary. The primary sensitivity variants remain distinct work; none are removed or represented as covered by this primary packet.

Finite output envelope: four64GiB exports, two1GiB master trees,4GiB control/log/margin =262GiB retained reservation, plus64GiB free floor. Each new producer write must reserve its full512MiB per-file hard limit within its own cumulative budget; torch's native file writer is covered explicitly. One writer per task makes that reservation sequential, and a parent monitor kills/reaps the exact process group on disk/log/time/interrupt failures. Partial outputs and diagnostics remain for diagnosis; a resource failure cannot classify or remove a scientific cell or trigger retry. This is a finite bound, not a measured claim that real exports fit. Exact admission must also reconcile concurrent retained reservations and actual free space with root's job ledger before execution; a df sample alone is insufficient if competing jobs can consume reserved space.
