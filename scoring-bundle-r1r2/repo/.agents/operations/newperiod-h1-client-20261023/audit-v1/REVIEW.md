The adapter requires those two fields to agree between base and expanded tensors, requires the selection receipt provenance to equal the tensor provenance with exactly those keys removed, then supplies that pre-extension view to the original auditor. Tensors and digest arithmetic are unchanged; no generic unknown-key relaxation exists.

The independent topK census reads every successful history event from the exact source receipts, reconstructs target sets from their hash-bound membership parquet and fixed reference collector panel, then uses the original independent maturity/participation arithmetic. Eventset `set_final_2h` is deliberately not used: it can contain a different collector panel. No training/validation event sample is used. Failed history records are retained in the source closure and excluded by the original success policy. History tables containing successful September-or-later events are rejected before membership reads. Production labels are never printed; labels are compared for equivalence only. The output contains per-event hashes and node cardinalities, plus boolean audit assertions and provenance.

Parallelism is 1–64 CPU workers, each processing a contiguous full-population chunk. Spawn avoids fork-after-Polars/Torch deadlocks. Each worker has one thread. Serial and two-worker records are required identical in synthetic tests. More workers reduce tensor-audit time, at the cost of copied history census memory. Resource readiness must bind the maximum history rows, total compressed source bytes, individual graph/history byte caps, actual CPUs/memory/job, and worker count. There is no generic claim that compressed sizes prove decoded memory sufficiency: the independent execution review must approve actual measurements/headroom. The fixed frozen client source closure is verified before any scientific import; the Python executable and torch/numpy/polars versions are bound. The production caller must supply Slurm CPU/memory values and the exact approved job ID. This code does not submit a job.
