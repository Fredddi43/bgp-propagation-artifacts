Required before integration:

1. **Enforce a real hard cap of eight.** `_resolve_workers` defines its cap from the configurable `max_workers` and affinity but omits `MAX_WORKERS`. Independent probe `_resolve_workers(64, 64, 500)` returned 16 under current affinity. Include the constant in the minimum, and test oversized explicit `workers` AND oversized `max_workers` together, plus smaller affinity/allocation caps.

2. **Disable cyclic GC around fork pools.** The parent may own about 1 TB of tracked prepared objects. Automatic child GC can touch unrelated inherited container metadata and cause large copy-on-write costs; Python explicitly documents this fork/GC interaction. Disable automatic GC in the parent before pool creation/fork, have a worker initializer keep it disabled, and restore the parent's exact previous enabled/disabled state in `finally` after workers drain, including startup/scoring failures. Children inherit the already-disabled state before their initializer runs. Do not add `gc.collect()` or a full-graph freeze pass to the scoring path. Reference counting remains active. These bounded pure scoring calls do not need automatic cycle collection. See [Python's official GC documentation](https://docs.python.org/3/library/gc.html#gc.freeze).

3. **Correct the invalid-input exception contract.** The new adapter does not always reproduce the serial `per_event_rows` first exception across two distinct failure phases. The original validates all rows label-free before scoring any row; chunks interleave those phases. Independent probe: an invalid label status on e0 and a committed seed mismatch on e1 makes serial raise the e1 preflight error and parallel raise e0's scoring error. Both reject. The owner explicitly accepted successful admitted-output equivalence plus fail-closed rejection of every invalid input, with honest documentation of this error-selection difference. This scope is scientifically acceptable: every validation still runs for any successful family, invalid input cannot yield a successful family, and the existing pre-label admissions and exact checkpoint byte bindings remain untouched. Correct the claimed universal first-error equivalence and add a mixed-phase invalid-input test proving both paths reject. A redundant full validation phase is not required.
